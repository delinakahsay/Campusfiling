Pushing to `main` deploys automatically. There is no build step: Vercel
serves the files as they are, so what is in the repository is what ships.

## Security headers

`vercel.json` is the only configuration file. It sets a Content Security
Policy of `default-src 'self'` with every directive self-only, which means
the deployed site cannot make a request to any other domain even if
someone later added code that tried to.

It also sets `form-action 'none'` (nothing can be submitted anywhere),
`frame-ancestors 'none'` (the site cannot be embedded in another page, so
it cannot be used in a phishing frame), `Referrer-Policy: no-referrer`,
`X-Content-Type-Options`, `Cross-Origin-Opener-Policy` and HSTS.

Two consequences worth knowing before you change anything:

- **No inline script.** An `onclick="..."` attribute or a `<script>` block
  inside an HTML file will not run. Put it in a file under `assets/js/`.
  This is why the glossary filter and the estimator's submit handler live
  in their own files.
- **No third party anything.** No analytics snippet, no embedded font, no
  CDN script will load. That is deliberate. If you need one, you are
  changing the privacy promise, so change `privacy.html` in the same
  commit or do not do it.

- **The AI reader works within this, not around it.** `connect-src 'self'`
  means the browser may only talk to this domain, which is exactly why the
  assisted reader posts to `/api/read-document` here and that function
  calls Anthropic server side. The policy did not have to be loosened to
  add it, and it should not be.

`node tests-browser.js` fails if any page requests anything offsite.

### Cache headers

There are none, on purpose. Filenames carry no content hash, so caching
assets would leave a returning visitor running a mix of old and new
JavaScript after a deploy. That already happened once during setup and
produced a confusing half hour. Vercel's revalidate-always default is
correct here.

## Supabase

The project exists and is configured, but **no application code talks to
it yet**. Login is the next phase. What is already set up:

- **Auto-expose new tables: off.** Supabase's own recommendation. A new
  table is private until you grant access to it deliberately.
- **Automatic Row Level Security: on.** An event trigger enables RLS on
  every new table in `public`, so a table cannot accidentally ship
  readable by anyone with the publishable key.
- **Auth Site URL** is `https://campusfiling.vercel.app`, and
  `https://campusfiling.vercel.app/**` is in the redirect allow list.
  Google sign-in will not work until both are set, which they now are.

The database password was generated by Supabase during setup and not
recorded anywhere. If you need it, reset it under Settings → Database.

### Environment variables on Vercel

Set on the `campusfiling` project, Production, as readable config rather
than secrets, because neither value is one:

```
NEXT_PUBLIC_SUPABASE_URL       https://tkldxfpzfmbojfxujlkx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY  sb_publishable_...
```

The publishable key is designed to be visible in browser code. It is safe
**only because** Row Level Security is on. If you ever turn RLS off on a
table, that key becomes a way for anyone to read it.

Never put the service role key in these variables or anywhere in this
repository. It bypasses RLS entirely.

### The Anthropic API key

The assisted document reader at `api/read-document.js` needs one variable,
and it is a real secret rather than readable config:

```
ANTHROPIC_API_KEY      sk-ant-...        (Production, mark as Secret)
ANTHROPIC_MODEL        claude-sonnet-5-5 (optional, defaults to this)
```

If the key was created at the organization level rather than inside a
workspace, Anthropic rejects the call with a 400 saying the request must
name a workspace. Two ways out, either is fine:

```
ANTHROPIC_WORKSPACE_ID   wrkspc_...   (only for an org-level key)
```

or create a new key from inside a workspace in the Anthropic Console,
which carries the workspace with it and needs no extra variable. The
function passes the header through whenever the variable is set and
ignores it otherwise, so setting it unnecessarily does no harm.

`ANTHROPIC_KEY` is accepted as an alternative name for the key, because
getting it slightly wrong costs a deploy and produces a 503 that reads
like a bug rather than a typo. Prefer `ANTHROPIC_API_KEY`, which is what
Anthropic's own tooling uses.

**A new variable does not reach a running deployment.** Vercel injects
environment variables at build time, so after adding or renaming one you
must redeploy before the function can see it. Deployments, then the menu
on the latest one, then Redeploy.

Add it under Settings, Environment Variables on the `campusfiling` project.
It must never appear in client code, in this repository, or in a committed
`.env`. The whole reason the reader goes through a serverless function
instead of calling Anthropic from the browser is that a key shipped to a
browser is a key anyone can spend.

Without it the site still works. Local reading is unaffected, and the
assisted reader returns a clear message saying it is not configured on
this deployment.

Cost is per document and only when someone presses the button, so a demo
of a dozen documents is negligible. If this is ever opened to a campus,
put a rate limit in front of the function first. An unauthenticated
endpoint that spends money is the obvious thing to abuse.

Note that this site has no build step, so a static page cannot read
`process.env`. These variables are groundwork for the login phase; when
that is built, the values go into the page through whatever mechanism that
phase uses.

### Why not the Vercel marketplace integration

Supabase's dashboard offers an "Install Vercel Integration" button that
leads to Vercel's **native** Supabase integration. That provisions a new
Supabase project owned and billed through Vercel rather than connecting
the existing one, which would have left two databases and a billing
relationship nobody wanted. Environment variables connect the real
project, stay free, and can be removed in a click.

## The rule that still holds

Do not put real student tax data in this database. Build the schema, build
the auth, seed it with generated sample profiles, and say so on the
privacy page. A panel will respect a deliberate boundary more than a
working login holding real income figures.
